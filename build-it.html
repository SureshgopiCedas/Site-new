The IO-list is the master list of the project. Build-IT checks it, then generates the repetitive code for every signal and device.

Why it matters

Test sooner. Fix less.

On a large project, thousands of signals are typed in by hand, often by several people. Every typo, missing column or duplicate becomes a bug that is found late, during FAT or on site.

Build-IT moves that work to the start. The IO-list is checked before anything is generated, and I/O testing can start right after import.

  • Equipment is defined before programming starts
  • Duplicates and column errors are caught before import
  • The same structure on every project, ready for CAPP libraries
